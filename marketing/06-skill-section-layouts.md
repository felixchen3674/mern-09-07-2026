# Skill Section Layouts

Twelve ways to organize the same keyword bank ([05-master-keyword-bank.md](05-master-keyword-bank.md)). Each layout lists its **category names** and the **buckets (B01–B28)** that feed each line. Pick one, copy the keywords from those buckets, delete anything you can't defend (anything marked † in the bank).

Layouts 1 and 2 are the two options already sketched in `skill-section.md`.

---

## How to make resumes look different (4 levers)

1. **Layout:** pick a different one of the 12 below.
2. **Subset:** you don't need all keywords from a bucket. Choose the 4–8 that match your projects and the target job.
3. **Order:** put your strongest line first, and your strongest keyword first in each line.
4. **Depth:** two students with the same layout can still differ by merging buckets (shorter resume) or splitting them (longer resume).

**Rules for every layout:** 5–8 lines total, 4–10 keywords per line, plain text, comma-separated, no skill bars or icons.

## The 12 layouts

### 1 · Classic Stack
*Balanced, safe default.*

| Category | Buckets |
|---|---|
| Languages | B01 |
| Frontend & Web | B02, B03, B04, B05 |
| Backend & APIs | B08, B09, B10 |
| Databases | B11, B12, B13 |
| Cloud & DevOps | B16, B17, B18 |
| Practices & Others | B14, B19, B20, B28 |

*AI gap:* add an AI line from B22–B26, or fold AI into "Practices & Others" for a non-AI role.

### 2 · Four Hats
*Short and role-focused. Good for one-page resumes.*

| Category | Buckets |
|---|---|
| Frontend | B01 (JS/TS/HTML/CSS), B02–B06 |
| Backend | B08–B15 |
| Testing & DevOps | B16–B21 |
| AI Engineering | B22–B27 |

*Reads like an architecture diagram. Suits systems-minded candidates.*

| Ship | B16, B17, B18 |
| Run & Observe | B21, B12 |
| Ways of Working | B28 |

### 5 · Proficiency Tiers
*Honest and scannable. Replace category names with levels.*

| Category | What goes in it |
|---|---|
| Proficient | Your 8–12 strongest tools (usually B01, B02, B03, B08, B11) |
| Experienced | Tools you've used on at least one project (B04, B09, B10, B19, B16) |
| Familiar | † items you can discuss (B13, B17 Kubernetes, B05 libraries, B02 Next.js) |

*Tip:* only use this if the Proficient line has at least 8 items you could defend.

*Different feel: two headings, longer lines. Works well in a narrow sidebar.*

## Quick picker

| Target role / situation | Try layouts |
|---|---|
| Full-stack generalist | 1, 6, 7 |
| React / frontend | 11, 2, 6 |
| Node / backend / platform | 10, 3, 7 |
| AI / LLM engineer | 8, 2, 7 |

| One page, little experience | 9, 2, 5 |
| Wants to show honest depth | 5, 12 |
| Consulting / client-facing | 7, 1, 4 |

## Handing layouts out

To avoid identical resumes, assign each student a layout number (e.g. by roll order, or `student number mod 12 + 1`) and let them swap with a role-based alternative from the picker if theirs doesn't fit the jobs they're targeting.
