# Technical Skills Bank

The **highest-level** skills only: the things a recruiter scans for in the *Technical Skills* section, and that usually appear in a job description. This is the bank the Skill Section Builder draws from.

**The test for an entry:** it must be either
1. a **named tool, framework, library, language or platform** (React, PostgreSQL, Docker, LangGraph), or
2. a **broad discipline that job descriptions list as a single phrase** (Microservices, CI/CD, Unit Testing, Agile).

**Out:** techniques, features, patterns and sub-concepts. Code splitting, lazy loading, MVC, input validation, error handling, bcrypt, OWASP Top 10, session auth, indexing, transactions, interceptors, `useEffect`, the diffing algorithm. Those belong in **project descriptions and experience bullets**, where [05-master-keyword-bank.md](05-master-keyword-bank.md) lists them.

**Also out:** anything conceptual-only (covered as interview questions but never built with, e.g. Redux, Next.js, Angular, Tailwind, Kubernetes, MongoDB). A student who has really built with one can add it by hand.

If you're unsure whether to add something, ask: *would this be a bullet under a project, or a word in the skills line?* Bullet → leave it out.

The builder reads the `### Sxx · Name` headings and the single line under each.
